## 2. Gateway interface (pg-service)

**Location:** `org.egov.pg.service.Gateway`

**Methods:**
- `URI generateRedirectURI(Transaction transaction)` — builds redirect URI including hash
- `Transaction fetchStatus(Transaction currentStatus, Map<String,String> params)` — fetches
  live status and returns a mutated Transaction (not a separate TransactionStatus object)
- `boolean isActive()` — reads `{name}.active` from `Environment`
- `String gatewayName()` — returns uppercase name e.g. `"AXIS"`, `"PAYTM"`
- `String transactionIdKeyInResponse()` — gateway-specific callback key for the transaction ID

**Discovery mechanism:** Spring `@Component` on each gateway class. `GatewayService` receives
`List<Gateway>` via `@Autowired` constructor injection. All gateways, active or not, are
instantiated at startup (constructor calls `environment.getRequiredProperty(...)` for all keys,
so missing keys cause startup failure regardless of `active` flag).

**Key difference in new SPI design:** `GatewayProviderFactory` / `GatewayProvider` replaces
`Gateway`. `fetchStatus` returns `TransactionStatus` instead of mutating `Transaction`.
ServiceLoader replaces Spring component scanning for discovery.

## 4. Gateway implementations — key details

### Axis (`AxisGateway`)

**Config keys read via `environment.getRequiredProperty`:**
```
axis.active
axis.currency          (default: INR)
axis.locale            (default: en_IN)
axis.merchant.id
axis.merchant.secret.key   (64-char hex, 32 bytes for HMAC-SHA256)
axis.merchant.user
axis.merchant.pwd
axis.merchant.access.code
axis.merchant.vpc.version  (default: 1)
axis.merchant.vpc.command.pay    (default: pay)
axis.merchant.vpc.command.status (default: queryDR)
axis.url.debit         (https://migs.mastercard.com.au/vpcpay)
axis.url.status        (https://migs.mastercard.com.au/vpcdps)
```

**Amount conversion:** rupees → paise (`× 100`), formatted as integer string via `Utils.formatAmtAsPaise`.

**Redirect URI construction:**
1. Build `Map<String,String>` with keys: `vpc_Version`, `vpc_Command`, `vpc_AccessCode`,
   `vpc_Merchant`, `vpc_Locale`, `vpc_Currency`, `vpc_ReturnURL`, `vpc_MerchTxnRef`,
   `vpc_OrderInfo` (= bank account number from additionalFields), `vpc_Amount` (paise)
2. Compute HMAC-SHA256 over all fields sorted by key: `AxisUtils.SHAhashAllFields(fields, SECURE_SECRET)`
3. Append `vpc_SecureHash` and `vpc_SecureHashType=SHA256` as query params
4. Return `UriComponentsBuilder.fromHttpUrl(MERCHANT_URL_PAY).queryParams(...).build().encode().toUri()`

**`fetchStatus`:**
- Removes `vpc_SecureHash` and `vpc_SecureHashType` from params before hash verification
- Makes GET call to `MERCHANT_URL_STATUS` with params: `vpc_Version`, `vpc_Command=queryDR`,
  `vpc_AccessCode`, `vpc_Merchant`, `vpc_User=AMA_USER`, `vpc_Password=AMA_PWD`,
  `vpc_MerchTxnRef=txnId`, plus the computed secure hash
- Response parsed as URL-encoded key=value pairs
- Success code: `vpc_TxnResponseCode=0`; failure = any other value
- Sets `gatewayTxnId = params.get("vpc_TransactionNo")`

**`transactionIdKeyInResponse()`:** `"vpc_MerchTxnRef"`

### PayTM (`PaytmGateway`)

**Config keys:**
```
paytm.active
paytm.merchant.id
paytm.merchant.secret.key
paytm.merchant.industry.type   (default: Retail)
paytm.merchant.channel.id      (default: WEB)
paytm.merchant.website         (default: WEBSTAGING)
paytm.url.debit    (https://securegw-stage.paytm.in/theia/processTransaction)
paytm.url.status   (https://securegw-stage.paytm.in/merchant-status/getTxnStatus)
```

**Amount conversion:** rupees format (e.g. `"51.23"`) via `Utils.formatAmtAsRupee`.

**Redirect URI:** Uses `PaytmChecksum.generateSignature(paramMap, MERCHANT_KEY)` from Paytm SDK.
Params: `MID`, `ORDER_ID` (= txnId), `CUST_ID` (userName), `INDUSTRY_TYPE_ID`, `CHANNEL_ID`,
`TXN_AMOUNT`, `WEBSITE`, `EMAIL`, `MOBILE_NO`, `CALLBACK_URL`, `CHECKSUMHASH`.

**`fetchStatus`:** POST to `MERCHANT_URL_STATUS` with JSON body `{"MID": ..., "ORDER_ID": ...}`,
signature via `PaytmChecksum`. Parses response JSON field `STATUS`; success = `"TXN_SUCCESS"`.

**`transactionIdKeyInResponse()`:** `"ORDER_ID"`

### PhonePe (`PhonePeGateway`)

**Config keys:**
```
phonepe.active
phonepe.merchant.id
phonepe.merchant.secret.key
phonepe.merchant.secret.index
phonepe.merchant.host          (mercury-uat.phonepe.com)
phonepe.url.debit              (/v3/debit)
phonepe.url.status             (/v3/transaction)
```

**Amount conversion:** rupees → paise (`× 100`).

**Redirect URI construction:**
1. Build JSON payload: `{"merchantId":..., "merchantTransactionId":txnId, "amount":paise, ...}`
2. Base64-encode the JSON string
3. Hash = SHA-256( Base64payload + url.debit + merchantSecretKey ) + `"###"` + secretIndex
4. POST to `https://{host}{url.debit}` with body `{"request": base64payload}` and
   header `X-VERIFY: {hash}`
5. Parse JSON response `data.instrumentResponse.redirectInfo.url`

**`fetchStatus`:** GET `https://{host}{url.status}/{merchantId}/{txnId}/status` with
`X-VERIFY` header. Parse `data.responseCode`; success = `"SUCCESS"`.

**`transactionIdKeyInResponse()`:** `"transactionId"`

**Note:** pg-service uses `DatatypeConverter.printHexBinary`; payment-gateway replaces with
`HexFormat.of().formatHex()` (Java 17 standard library).

---

### PayU (`PayuGateway`)

**Config keys:**
```
payu.active
payu.merchant.key
payu.merchant.salt
payu.url           (test.payu.in)
payu.url.status    (test.payu.in)
payu.path.pay      (_payment)
payu.path.status   (merchant/postservice.php)
```

**Amount conversion:** rupees format via `Utils.formatAmtAsRupee`.

**Redirect URI construction:**
1. Hash sequence: `key|txnid|amount|productinfo|firstname|email|||||||||||{salt}`
2. Substitute fields, compute SHA-512 (`MessageDigest.getInstance("SHA-512")`)
3. POST form-urlencoded to `https://{url}/{path.pay}` with params: `key`, `txnid`, `amount`,
   `productinfo`, `firstname`, `email`, `phone`, `surl=callbackUrl`, `furl=callbackUrl`, `hash`
4. Follow redirect — `RestTemplate.postForLocation(...)` returns the final redirect URI

**`fetchStatus`:** POST form to `https://{url.status}/{path.status}` with
`command=verify_payment`, `var1=txnId`, `key=MERCHANT_KEY`, `hash=SHA512(...)`.
Parse JSON response field `transaction_details.{txnId}.status`; success = `"success"`.

**`transactionIdKeyInResponse()`:** `"txnid"`

## 6. TransactionService lifecycle

### `initiateTransaction(TransactionRequest, tenantId, clientId)`
1. `validator.validateCreateTxn(txn)` — null checks, gateway active, amount > 0
2. `paymentsService.validatePayment(txn, tenantId, clientId)` — bill exists, amount matches
3. `enrichmentService.enrichCreateTransaction(txn, tenantId, clientId)` — generates txnId,
   sets PENDING status, fetches bank account, creates/searches user, appends txnId to callbackUrl
4. Build `TransactionDump` (txnId + auditDetails)
5. If `skipGateway(txn)` (txnAmount == 0):
   - Set status = SUCCESS
   - `paymentsService.registerPayment(...)` immediately
6. Else:
   - `gatewayService.initiateTxn(txn)` → URI
   - Set `txn.redirectUrl`
   - Set `dump.txnRequest = uri.toString()`
7. `transactionRepository.saveTransaction(txn)`
8. `transactionRepository.saveTransactionDump(dump)`
9. If broker enabled: `producer.push(createTopic, txn)`
10. Return txn (with redirectUrl)

### `updateTransaction(Map<String,String> params, tenantId, clientId)`
1. `validator.validateUpdateTxn(params)` — extract txnId from params (checks all gateway TxnID keys)
2. Fetch existing transaction from DB by txnId
3. If already SUCCESS/FAILURE: return as-is (idempotent)
4. `gatewayService.getLiveStatus(txn, params)` — fetch authoritative status from gateway
5. Update `txn` fields from live status
6. If now SUCCESS: `paymentsService.registerPayment(txn, tenantId, clientId)`
7. `transactionRepository.updateTransaction(txn)`
8. `transactionRepository.saveTransactionDump(dump)` (with raw response)
9. If broker enabled: `producer.push(updateTopic, txn)`
10. Return updated txn

### `skipGateway(Transaction)` condition
`new BigDecimal(txn.getTxnAmount()).compareTo(BigDecimal.ZERO) == 0`

## 7. EnrichmentService

Steps in `enrichCreateTransaction`:
1. `txn.setTenantId(tenantId)`
2. Fetch bank account from Registry → store in `additionalFields.BANK_ACCOUNT_NUMBER`
3. Generate txnId via IdGen (template = `TxnID`, tenantId substitution var `TENANTID`)
4. Create or search user via `UserService` (controlled by `pg.is.user.create.enabled`)
5. `txn.setTxnStatus(PENDING)`, `txn.setTxnStatusMsg("Initiated")`
6. Merge `taxAndPayments` into `additionalDetails` (preserves existing JSONB object or creates new)
7. Append `?eg_pg_txnid={txnId}` to `callbackUrl` (this is how update knows which txn is returning)
8. Build `AuditDetails` (createdBy = clientId, createdTime = now)

**IdGen template code:** `TxnID` (config key: `idgen.txn.id.template.code`)

## 8. TransactionValidator

### `validateCreateTxn(Transaction txn)`
- Gateway not null, not empty
- Gateway is active (`gatewayService.isGatewayActive(txn.getGateway())`)
- `txnAmount` not null, parseable as `BigDecimal`, >= 0
- `billId` not null/empty
- `callbackUrl` not null/empty
- Throws `CustomException` from `org.egov.tracer.model`

### `validateUpdateTxn(Map<String,String> params)`
- `gatewayService.getTxnId(params)` must be present (Optional.isPresent())
- Fetches transaction from DB; throws if not found
- Returns the existing `Transaction`

## 11. REST layer

Single controller: `TransactionsApiController`

| Method | Path | Handler | Notes |
|---|---|---|---|
| POST | `/transaction/v3/_create` | `TransactionService.initiateTransaction()` | Returns transaction with `redirectUrl` |
| POST | `/transaction/v3/_update` | `TransactionService.updateTransaction()` | Gateway callback; body is key=value map |
| GET | `/transaction/v3/_search` | `TransactionRepository.fetchTransactions()` | Takes `TransactionCriteria` |
| GET | `/gateway/v3/_search` | `GatewayService.getActiveGateways()` | Returns Set\<String\> |

**Required headers:**
- `X-Tenant-ID` — required on all endpoints
- `X-Client-ID` — required on create and update

**Response envelope:**
```json
{
  "ResponseInfo": { "apiId": "...", "ver": "...", "ts": ..., "status": "successful" },
  "Transaction": { ... }
}
```
Create response is `TransactionResponse` (single transaction).
Search response is `TransactionResponse` (list of transactions).

**`eg_pg_txnid` label:** The constant `PgConstants.PG_TXN_IN_LABEL = "eg_pg_txnid"` is the
query-param key appended to callbackUrl and the primary lookup key for `getTxnId()`.
